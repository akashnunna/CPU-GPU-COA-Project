CPU vs GPU COMPARISON SUMMARY
================================================================
CPU: 12th Gen Intel(R) Core(TM) i5-12450H (12 logical cores, 8 torch threads)
GPU: NVIDIA GeForce RTX 2050 | CUDA (torch build): 13.0 | torch 2.14.1+cu130
Python 3.13.3 | torch 2.14.1+cu130

1. TRAINING TIME
   CPU total training time : 1404.7 s  (average 93.6 s/epoch)
   GPU total training time : 309.7 s  (average 20.6 s/epoch)
   Training speedup (CPU time / GPU time)  : 4.54x
   Reduction in training time              : 78.0 %
   -> In this experiment the GPU finished training faster than the CPU.
   GPU warm-up (reported separately): 0.79 s; GPU peak memory allocated: 367.6 MB

2. PREDICTIVE QUALITY (same held-out test set)
   CPU-trained model: accuracy 0.5502, macro-F1 0.3765, weighted-F1 0.5986
   GPU-trained model: accuracy 0.6637, macro-F1 0.4403, weighted-F1 0.6852
   Difference in macro-F1 (GPU - CPU): +0.0638; accuracy: +0.1134
   The two models were trained separately, so small differences can come from training randomness; this experiment does not isolate the cause.
   Macro-F1 matters most here because the classes are imbalanced (nv is by far the largest).

3. INFERENCE (same weights, same test images on both devices)
   Batch size 1 (single-image inference):
     latency speedup, compute only        : 4.61x (CPU time / GPU time)
     latency speedup, incl. data transfer : 4.34x
     transfer overhead on GPU             : 0.053 ms/image
   Batch size 32 (batch inference):
     latency speedup, compute only        : 11.45x (CPU time / GPU time)
     latency speedup, incl. data transfer : 10.43x
     transfer overhead on GPU             : 0.034 ms/image

4. FAIRNESS CHECK
   Same model, split, epochs, batch size, optimizer, learning rate, class weights, seed and preprocessing.
   Known differences that cannot be removed:
     - pin_memory is enabled on the GPU run only (standard for CUDA transfers).
     - Dropout random numbers come from different generators on CPU and GPU, and floating-point results differ slightly between devices.
   Each device was trained once, so the speedup comes from a single run per device.

5. BACKGROUND (general computer-architecture ideas; NOT measured by this experiment)
   - A GPU has thousands of simple cores that run many multiply-add operations in parallel,
     which suits the large matrix/convolution work in a CNN; a CPU has few, more complex cores.
   - A GPU is only fully used when each step has enough work (e.g. larger batches / bigger models).
     A small model with a small batch may leave much of the GPU idle.
   - Data loading and augmentation run on the CPU in both experiments, and each batch must be copied
     from CPU memory to GPU memory; this transfer cost is shown in the 'incl. transfer' inference results.
   - The first GPU use includes one-time start-up work; this run reports the warm-up separately.
